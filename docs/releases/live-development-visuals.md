# Development visuals in operational reporting

The actual facilitator participant screen now shows the shared first-review/current-stage bars and a selectable dated development chart before the evidence disclosures. It starts with the support priority and allows the facilitator to choose another capability. Authored stages, evidence criteria and scoring are unchanged.

Programme outcomes already use the shared capability bars, individual change distribution and authorised-group heatmap. New integration journeys exercise these through the operational staff workspace, alongside the actual facilitator participant workflow. They check the permitted API scope, selected capability, refresh, empty evidence, group switching, responsive layout and console errors.

These are displays of reviewed programme evidence. The fictional programme remains a separate demonstration dataset. Missing or withdrawn reviews do not become chart values, and private reflections are excluded.

Release requires the complete npm run verify contract on the exact pull-request head, plus deployed public regression checks. Signed-in programme records are not used as development fixtures.

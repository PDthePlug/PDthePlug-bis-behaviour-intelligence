# Reporting measures and interpretation

This complements `metric-register.json`, which lists every authored Universal computed field and indicator binding, with named inputs and operations. The calculations use source definitions, not a newly invented composite score. The SQL definition hashes in the staging/production inventories match for these common functions.

| Measure / presentation | Source and calculation | Evidence class and practical meaning |
| --- | --- | --- |
| Eligible participants | Active cohort membership, active learner and latest granted product consent in `sponsor_cohort_evidence_flow` and sponsor aggregate functions; count distinct permitted members | Administrative coverage denominator, not attendance or observed behaviour |
| Enrolled, started experiment, completed | Version-scoped `lab_enrollments`; counts of enrolments, non-null experiment start and completed status respectively | Separate recorded milestones; these counts are not a nested funnel or competence rating |
| Lab stage participation / response count | Active, answered `evidence_records` anchored to `responses`, matching cohort Lab/version; distinct participants and source records grouped by baseline/I1–I9 | Recorded evidence coverage, not stage completion; no private response wording is returned |
| Anchored measures | `measurement_values` with status VALUE and a matching permitted `measurement_sources` RESPONSE anchor | Source-linked calculations available for review; quantity does not establish improvement |
| Universal values | `lib/universal-lab-v2.mjs`, exactly the operations and field references in the published definition; missing input handling is operation-specific and registered | Calculation from recorded inputs. Inputs can themselves be self-report. A derived value is not independent observation or proof of cause |
| Learning reached / completed by touchpoint | `handbook_progress` and release/day mappings via `sponsor_cohort_learning_summary`; permitted participant counts per authored day | Page activity/completion record, not attendance, mastery or a reason for absence |
| Understanding / support signal rates | Authored formative learning checks through `sponsor_cohort_learning_checks`; understood responses divided by recorded signals; uncertainty/another-example signals divided by recorded signals, expressed as percentages | Participant self-report. Response denominator can include several responses from the same participant; not unique-participant mastery |
| Paired starting/later ratings | Named comparable pre/post fields via learning-summary aggregates; mean pre and mean post among participants with both; display post minus pre in scale points with paired sample | Self-report from a paired sample; missing pairs excluded, not assigned zero. Not assessed skill or programme effect |
| Legacy Habit adherence | Eligible opportunity events in `lib/bis-metrics.mjs`; round(alternative uses / eligible opportunities × 100); unavailable if no opportunities or invalid alternative-use evidence | Recorded action in declared situations. Valid no-opportunity days are distinct from missed days and unsuccessful attempts |
| Legacy prediction accuracy / gap | Prediction and observed adherence; accuracy `max(0, 100 − abs(prediction − adherence))`; group gap is the mean of individual differences | Expectation compared with recorded action; not a difference between two group means. Universal reports do not inherit this legacy formula |
| Legacy repeat-situation direction | Comparable first/later opportunity records via version-scoped sponsor outcomes; count participants whose later response moves toward the planned alternative, stays the same or changes otherwise | Direction within the available situations, not lasting change or causal attribution |
| Observation / opportunity / sufficient-evidence counts | Valid observation records, opportunity flags and authored sufficiency rule through sponsor outcomes | How much usable evidence exists. Coverage and change are different questions; missing evidence does not establish failure |
| Question patterns | `sponsor_cohort_question_patterns`, versioned `question_analysis_registry` classification and active structured answers; permitted numeric means or category counts with respondent count | Descriptive structured answers. Narrative/private text excluded. A numeric average is not given an unsupported capability interpretation |
| Shared-task human assessments | Explicit learner submission IDs, immutable rubric version/criteria and saved human review in `bis_assessment_report`; authored total/maximum and mean over reportable saved assessments | Assessment of chosen shared tasks by a human, separate from private reflections and self-report. An empty rubric does not acquire an invented score |
| Support follow-up | Restricted support/case events, authorised aggregate `sponsor_cohort_organisational_learning` | Recorded follow-up only; no recorded response does not prove no support occurred. Case narratives remain restricted |
| Programme decisions | Explicit authorised `programme_decisions` and review records | The team's saved decision and evidence basis, not an automated prescription to redesign the programme |

Whole cohorts below five participants are suppressed. Positive cells below three are withheld according to each SQL function; some functions also withhold zero cells. The renderer preserves null/unavailable rather than turning it into zero. It must not attempt to undo upstream suppression. Charts have readable data alternatives; units, denominators, contributing sample and evidence boundaries remain available in the shared report model and exported PDF.

`buildProgrammeReport` produces descriptive findings from already authorised aggregates and retains `sourceRefs`, basis, sample, population and boundary. Discussion prompts are inference bounded by those records. No report establishes cause, lasting capability, personality or programme effectiveness. Sponsors receive practical participation, evidence coverage, paired self-report and shared assessment information without private learner narratives.

Actual staging verification used twenty explicitly synthetic completed Habit enrolments: six computed fields matched persisted values; sixteen portfolio metrics had verified source references; the original-evidence report retained 119 records and 48 calculation-history entries at that checkpoint. A private P3 share was denied; one chosen P2 record alone reached the assigned facilitator, a human review restored on refresh, and revocation removed current access. Sponsor payloads and downloads excluded the private-reflection marker and structured-evidence narrative. These are software verification results, not measured programme outcomes.

Remaining boundaries are tracked in `open-findings.md`: full editorial review of all source preparations, all live edition/state variants, and authenticated production verification. This report does not close those entries.
